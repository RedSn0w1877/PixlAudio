## What was NOT the cause (checked)

- BiniLyrics endpoint, redirect handling, headers, JSON/TTML parsing: all fine against the live service.
- The Spotify import keeps the ISRC: `SpotifyApiService.PLAYLIST_TRACK_FIELDS` asks for `external_ids(isrc)` and
  `SpotifyRepository.toSpotifySongEntity` stores `track.externalIds?.isrc` (`SpotifyRepository.kt:1056`);
  `SongIsrcResolver` reads it back by `spotifyId`. Spotify's February 2026 change removed `external_ids` from Track,
  but the March 2026 changelog reverted that. (Rows imported from YouTube Music search, `toYouTubeMusicSongEntity`, have no ISRC by nature.)
  No change to `data/spotify` was needed. If a Spotify response ever omits `external_ids`, lookups fall back to strict title/artist/duration.
- The lyrics sheet (M3E restyle, PR #17): the diff only removed the glass branches. State is collected from
  `stablePlayerState` with `collectAsStateWithLifecycle` + `derivedStateOf`; the position source is
  `PlaybackStateHolder.framePositionMs()` (MediaController position); synced, word-timed and plain lyrics have separate branches.
  No empty composable or scrim/colour regression found.
- The automatic on-device alignment (`AutomaticStudioManager`, "lyrics_sync") only upgrades lyrics in the background
  (charging, app off screen, local audio). It never gates the plain online lookup, which runs from the player on every song change.

## Root causes found and fixed (proven by reading; no device log was available)

1. **A manual search could leave the lyrics screen on "Loading" forever** (`LyricsStateHolder.kt`, the old
   `fetchLyricsForSong` / `searchLyricsManually`). Both reused `loadingJob`, so tapping "Find or import lyrics" cancelled the
   automatic load in flight. The cancelled load never ran `onLyricsLoaded`, so `isLoadingLyrics` stayed true, the status view
   kept showing the spinner, and `LyricsSheet`'s `LaunchedEffect(isLoadingLyrics)` closed the manual dialog. Now the user's
   search has its own `searchJob`. Lyrics that arrive through `songUpdates` also clear the spinner
   (`PlayerViewModel.kt`, the collector), and a late "nothing found" from the automatic load no longer wipes lyrics the user's
   search put there (`onLyricsLoaded` keeps the existing lyrics on null).
2. **No negative cache, no shared lookup, no overall timeout** in `LyricsRepositoryImpl.getLyrics`. Every skip back to a song
   with no lyrics re-ran all four catalogs (BiniLyrics, AMLL, NetEase, LRCLIB with up to 6 strategies and 3 retries each),
   a prefetch and the player could race the same song, and the lookup had no ceiling. Now: one shared lookup per song
   (callers join it; it outlives a cancelled caller), a 30 s ceiling, a 5-minute negative cache (`NEGATIVE_TTL_MS`).
   Retry (`forceRefresh = true`) bypasses both the negative cache and BiniLyrics' own 30-minute memo.
3. **Streamed songs walked local-file sources** (`getLyrics`): for a `spotify://` song the default source order
   (EMBEDDED_FIRST) first tried to copy the "file" through the content resolver and read tags, which can only fail. Songs with no
   path and no `content://`/`file://` URI now go straight to the online sources. Offline downloads (file URIs) keep the tag path.
4. **No way to try again from the not-found state.** The "No lyrics for this song yet" card only offered the dialog.
   `LyricsStatusContent` now has "Try again" (`PlayerViewModel.retryLyricsForCurrentSong`), beside the existing
   "Find or import lyrics" (manual search by title/artist) and "Sync it yourself".
5. **Duration tolerance on an ISRC hit** (`BiniLyricsSource.lookup`): an ISRC already names the recording, but the 3 s duration
   check could still throw it away when Spotify and Apple cut the master a few seconds apart and then fall through to the
   stricter title search. ISRC hits now allow 8 s (title matches stay at 3 s; the "starts past the end" sanity check is unchanged).

## Added

- Prefetch: when the current song's lyrics start loading, the next queue song is looked up 2 s later with the same
  deduplicated, negatively cached path (`LyricsStateHolder.prefetchLyricsForSong`, `PlayerViewModel.prefetchLyricsForNextSong`).
  The lyrics-source preference is respected; there is no separate "automatic lyrics" switch for the online lookup (the
  Settings switch of that name controls the on-device alignment only), so the online lookup is always on.
- Tests (JVM, fake network): `LyricsLookupFlowTest` (ISRC then title/artist order, BiniLyrics then LRCLIB fallback and disk cache,
  negative cache, Retry bypass, a miss that turns into a hit on Retry, one shared lookup for three concurrent callers,
  no content-resolver access for a streamed song) and `AppleTtmlRealFormatTest` (real lrc.red TTML structure: word, line, unsynced,
  clock times, a non-TTML body). The existing `BiniLyricsSourceTest` already covers selection, back-off and redirects.

## Risks / not done

- Negative cache is 5 minutes: opening the app offline marks the song "no lyrics" for that long; "Try again" bypasses it.
- `acceptLyricsSearchResult`, `importLyricsFromFile` and `translateLyricsViaAi` still persist through numeric ids only; a song whose
  id is `spotify_<id>` (unmirrored) keeps a manually picked result for the session but not across restarts. Mirrored Spotify
  songs have numeric ids and are fine.
- Track rows with no ISRC (YouTube-Music-search imports) depend on strict title/artist/duration matching.

## Phone checks (plain)

1. Play a popular Spotify song, open the lyrics: after a moment the lines appear and light up in time. The footer says
   "Lyrics: BiniLyrics" when it came from there.
2. Skip to the next song: its lyrics should already be there or appear within a second or two.
3. Play an obscure track: the card says "No lyrics for this song yet" with "Try again", "Find or import lyrics" and
   "Sync it yourself". "Find or import lyrics" must open its dialog and stay open (this used to hide behind a stuck spinner).
4. Airplane mode, play a song with no cached lyrics, then go online and tap "Try again": lyrics appear.
5. Skip back and forth between two songs with no lyrics: the second visit is instant (no spinner).
