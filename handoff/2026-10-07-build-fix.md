# 2026-10-07: main builds again, and CI runs on every push

## What broke
- Dependabot PR #8 (77 updates, merged 2026-10-06) moved `androidx.compose.material3` from 1.5.0-alpha22 to 1.5.0-alpha29.
- alpha29 removed the `Slider(value, onValueChange, …, thumb, track, valueRange)` overload, so `:app:compileDebugKotlin` failed. The nightly APK (run 37616787094) failed the same way at `compileReleaseKotlin`.
- `rememberTooltipState()` became `@ExperimentalMaterial3Api`.

## The fix
- New `presentation/components/ValueSlider.kt`: the removed overload rebuilt on the `SliderState` API. It works the way the library's own value-based Slider does: one state per steps/range, with the caller's value pushed in on every composition.
  - Don't swap it for `rememberSliderState`. That one is saveable and never picks up a new value, so sliders driven by a ViewModel would freeze.
- Call sites switched to it: CastBottomSheet, TimerOptionsBottomSheet, CreatePlaylistScreen, EditTransitionScreen, EqualizerScreen, NavBarCornerRadiusScreen. The cast thumb uses `Thumb(isVertical = false)`.
- `LibraryActionRow` opts in to the experimental tooltip API.

## CI
- New `.github/workflows/android-ci.yml` runs on every push to any branch (handoff/, docs/ and Markdown changes excepted). It also runs on pull requests and on demand.
- Steps: `:app:compileDebugKotlin`, `:app:testDebugUnitTest` (reports uploaded on failure), `:wear:compileDebugKotlin`, `:app:assembleDebug -Ppixelplay.enableAbiSplits=true`.
- The arm64 debug APK is uploaded as artifact `pixlaudio-arm64-debug-apk`.
- First green run: 37693509975 on `fix-build-and-ci`.
- phone-debug, phone-release, wearos-apk, codeql and nightly now trigger on `main` instead of `master`, which doesn't exist.

## Not verified
- Nothing has run on a phone. The sliders should look and feel unchanged: cast volume, sleep timer, equalizer, transitions and nav-bar radius.
